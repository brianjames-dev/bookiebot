## Design details for the next slices

- Keep effective intervals in the two existing hidden schedules; metadata appended after original columns. Preserve baseline versions from `0001-01`. End dates exclusive; a change replaces that plan from the selected month forward. Settings log retains command/audit evidence for replaced future plans. Raw literals only; user bill names never become formulas.
- Subscription migration should promote the complete valid legacy subscription source into versioned hidden authority on its first explicit confirmed subscription Save. Each hidden tab can enroll independently; bill-only edits needn't migrate subscriptions. Then legacy sync must not overwrite managed sources. Visible Subscriptions is a projection. Do not append price versions without replacing old SUMIF references with period-aware formulas. Direct prior-month numeric results must remain identical.
- Ordinary subscriptions can remain schedule-derived virtual charges. A bill using a monthly budget source (all variable/new fixed bills and split subscriptions) needs a stable monthly source marker. Once a plan has a monthly source, keep it for subsequent versions to preserve repayment identity. Exclude its schedule occurrence from totals when its monthly source is used. This avoids migrating every subscription into physical monthly payment rows unnecessarily.
- Variable sources record only the explicitly entered amount; estimates stay projected. Fixed monthly sources use effective-period formulas, queued until their withdrawal date under existing bill semantics. Source-label identity stays stable even if display name changes.
- Existing charges/splits remain in native Transactions/Shared editors. New monthly amounts use canonical existing writers/review guards. New recurring split occurrences use configured defaults only, with exact-once source action lineage and due-date processing. New recipient source rows can be provisioned only for verified configured-plan lineage; existing arbitrary bill projection guards remain.
- Prefer appending a small managed Bills source block below existing monthly data, with verified named anchors; avoid shifting existing source/action-log row positions. Add its C/D references to Needs/Wants subtotals safely. Rebind new-month formulas in Apps Script. Direct version-row cell references selected for each fixed month avoid complicated date-string SUMIF criteria, but every confirmed config write must update all affected source/view formulas atomically if version row positions move.
- Preserve already recorded current charges too. Compute `earliestEffectiveMonth` on the server from gross/canonical charge state: if this month's charge exists, configure from next month and open its existing transaction editor for corrections. Missing timing can be repaired for the current month without rewriting amounts. Defaults have server-owned `split_starts_on` so an already elapsed automatic charge is not newly split. A newly recorded variable amount can explicitly review its default split, regardless of its earlier due day.
- Before source/formula batches, hold the existing `undo._RECENT_MUTATION_LOCK` and `reimbursements.projection.projection_lock(store)` (PG advisory lock) and revalidate the full snapshot. This serializes receipt/correction projections without inventing another financial writer. Config formulas must not overwrite received/recorded numeric amounts. Freeze prior calculated subscription subtotals/known automatic source values when needed so later visible projection prices cannot change historical numeric results.
- For percentages in recurring defaults, extend the existing NotchedSplitControl with an optional percent unit (default money unchanged), total=10000, same native circles/income icon/slider. Future By income remains dynamic per actual charge; don't freeze a client-supplied income ratio. Actual payment splits retain native exact-cent controls.
